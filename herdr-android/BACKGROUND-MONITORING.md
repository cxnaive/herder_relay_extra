# 常驻监控与完成提醒 · Android 0.2.11

## 使用

1. 覆盖安装同签名的 `Herdr-Pocket-0.2.11-debug.apk`，不必卸载、不必重新配对。
2. Agent 列表顶部或“我的设备”点 **开启常驻监控 / 完成提醒**。
3. 查看说明并点“开启常驻监控”，允许通知权限。通知栏出现 **Herdr 常驻监控**，显示连接/待确认数量；可直接点“停止监控”。
4. **默认关注所有 Agent**，后续新建的 Agent 自动进入监控。要关闭某一个，在 Agent 卡片或对话 `⋯ → 关闭此 Agent 完成提醒`；再次进入可开启。关闭后卡片显示“完成提醒已关闭”。这是本机通知设置，不会修改或停止远端 Agent。
5. 在“常驻监控 → 系统设置”允许完成通知的声音/弹出，并把 Herdr Pocket 的电池策略设为“不优化/不受限制”；按手机厂商要求允许后台、自启动。

完成通知显示 Agent / Tab 名称、电脑、工作空间，时间可用时附用时。点击打开同一会话的对话；已替换的会话回到列表，不按同名或复用 pane ID 打开其他 Agent。锁屏使用通用“Herdr Agent 已完成”文案，不展示对话、命令或文件内容。

## 完成提醒的声音

- 常驻“Herdr 常驻监控”状态通知保持静音，不因每次状态更新响铃。真正的 Agent 完成提醒使用独立“Agent 完成提醒”通道；新安装显式设置系统默认通知铃声和振动。
- 打开“常驻监控 / 完成提醒”→“测试完成提醒”，通过同一个完成通道发一条标为测试的系统通知。它不启动监控、不连接 Relay、不修改 Agent 或完成轮次记录。通知权限/通道关闭时明确提示未发送。
- 没声音时点“完成提醒声音与弹出设置”，直接进入该通道的系统设置，将提醒改为有声并选择铃声。设置页会提示已能读取的静音/振动模式、通知音量为零、通道静默、未选铃声及勿扰情况；这些检查不能证明扬声器实际出声，请用测试通知确认。
- 0.2.13 沿用原来的 `agent-completed` 通道 ID。Android 保留已创建通道的用户设置，覆盖安装不能强制取消静音；也不会新建替代通道或用媒体/闹钟声音绕过用户的勿扰设置。手机音量、厂商策略和系统通知节流仍可能影响声音。

## 这是常驻连接，不是系统推送

- 不需要无障碍、root、额外辅助 APK、FCM 或厂商推送账号。复用现有原生 TCP/WSS E2EE 连接，不增加服务器端口。
- 前台页面与监控服务共享 **一个 RelayEngine/设备凭据写入者**。页面关闭只暂停自己的历史/终端订阅和请求；只要服务仍在运行，加密连接继续保持。
- Android 前台服务为用户手动开启的 `specialUse`，有常驻通知和停止按钮。没有把长期监控伪装成有时限的 `dataSync`，也没有使用无障碍/精确闹钟来保活。如果以后上架 Play，服务用途仍需按平台规则审核。
- 服务持有可释放的 partial wake lock（10 分钟超时、5 分钟续期），停止/权限撤销/销毁时释放，不点亮屏幕。**会增加耗电**；这不能绕过 Doze 或厂商后台限制。
- 系统可能重启 `START_STICKY` 服务，但不保证。强行停止、断网、深度省电或厂商清理可导致延迟/丢失。没有开机广播自动启动；**手机重启后请打开 App**。已保存开启状态且通知权限可用时，会从可见页面恢复服务。
- 这不是离线通知队列或云端唤醒。已监控会话重连时核对最新轮次；离线期间若完成多轮，只检查最新轮次，不承诺逐条补发所有历史完成事件。

## 检测及去重

- 只监控当前配对电脑的完整、已确认 inventory；断开、库存未同步或会话身份更换时，不把消失当成完成。
- 正常网络下每个 Agent 约 15 秒读一次状态；一次只有一个监控查询，8 秒超时，Agent 很多或链路慢时一轮耗时会更长。只取元数据，不在后台读取整段对话、终端或文件。
- Codex 使用 Relay `agent_run_state_v1`，根据真实 `turn_id` / `done` 判断。失败、等待审批、取消、中断都不伪装成“成功完成”。其他 Agent / 旧 Relay 根据观察到的 Herdr working/blocked → idle/done 转换判断，精度依赖后端状态。
- 第一次读到一个会话时建立基线，不弹出旧完成事件。已建立基线后，即使短任务在两次查询间完成，也能根据新的 Codex turn ID 检出。单次重连和重复状态不会重复弹通知。
- 去重先持久化再发系统通知，是 **at-most-once**：崩溃在两步之间可能漏掉一次，而不是反复通知。保留最多 1024 个身份 / 每身份 8 个近期完成轮次，过期 30 天；异常/过期记录重新建立基线。重复的相同观察不会每 15 秒重写存储。
- 提醒关闭项按电脑、server、workspace、Agent session 的哈希保存；没有 session 时用 terminal 身份。不按标题、目录或 pane 序号匹配，因此重命名和 Relay generation 更新不改变选择，也不会静音另一个同名 Agent。重新开启单个提醒会先建基线，不追发静音期间的旧完成事件。
- 显式停止监控清除检测基线但保留单个 Agent 的关闭设置。撤销系统通知权限会停止服务并释放 wake lock，避免无通知地耗电。单独禁用完成通知通道时，常驻状态明确提示去系统设置开启。

## 实现与验证

主要代码：`SharedRelay.kt`、`AgentMonitorService.kt`、`AgentMonitor.kt`、`MonitorPolicy.kt`、`MonitorNotifications.kt`、`MonitorSettingsUi.kt`。

测试包括：默认全部、新 Agent、单个静音、首次快照、跨重连/进程去重、被移除/替换会话、权限拒绝/撤销、前台服务 stop/wake lock、Android 15 声明、锁屏隐私、点击通知打开确切对话，以及前台 Activity 销毁后仍由服务持有连接。

独立生成的本地 TCP fixture 实际执行 gateway 握手、ECDH/HMAC/AES-GCM E2EE 和 chunk framing。验证前台→后台后同一个连接继续轮询，两个 Agent 中只通知未静音者，断线重连不重复，新轮次再次完成可提醒。fixture 拒绝后台读取对话/终端或调用任何写操作。

**未连接用户手机，也未在真实厂商省电系统下验证锁屏行为。**Robolectric/native graphics/Socket 测试不等于真机验证。此版本只更新 APK；电脑 Relay 保持 `0.23.5+codexfix.8`，Gateway/Herdr/Agent 不重启。
