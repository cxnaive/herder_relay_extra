# 手机终端：历史与附加按键

Android 0.2.22（`android-v0.2.22`），沿用 Relay codexfix.11 / Gateway codexfix.6，**不需要重新配对或更新服务端**。

## 查看更早输出

- 在终端正文内上下滑动；向下拖动正文可看更早内容。开始翻阅后暂停自动跟随，新快照不会强制拉回底部；点「回到底部」恢复跟随。
- 拖到已加载内容的顶部，或点「更早输出」，会只读请求更多终端行：初始 500，每次增加 1,000，最多请求 10,000。显示加载动画，读取期间暂停远端输入按键，避免和历史请求交错。
- 补到更早行时保持阅读位置；失败/连接中断不清空当前已读画面，不自动重发任何输入。当前终端画面只保存在内存，不是跨进程的持久终端日志。
- 「手机换行」适合阅读；「原始列宽」保留电脑布局并允许横向滚动。这两项都不会调整电脑终端尺寸。

### 为什么请求了更多行，还是没有旧内容？

App 展示的是 **Herdr 提供的真实终端快照**，并不是从对话日志拼出的模拟终端。一些全屏程序/备用屏幕只提供当前屏幕；请求 1,500 行不代表一定有 1,500 行。在这次部署的只读检查中，两个 Codex 终端请求 500 / 1,500 行，均返回同一屏 47 行。

没有增加行数时会明确显示电脑返回了多少行，并停止反复自动请求。再次点「更早输出」可选择：

- **远端 PgUp 翻页**：向电脑端程序发送 Page Up。PgDn 可往回翻；效果取决于目标程序是否支持这些按键。**会改变电脑端正在显示的程序视图**，不是读取手机本地缓存。
- **切到对话看历史**：读取 Agent 的结构化对话记录。
- **重新请求更早输出**：在电脑输出变化后重新尝试。

不会通过手机滑动偷偷发送 PgUp，不启用会滚动电脑真实窗格的 text/recent 历史采集回退，也不把不同快照直接拼接成可能重复/错序的历史。电脑未提供的旧终端输出无法仅靠 App 恢复。

## 退格、回车和功能键

输入框是**手机本地待发送文本**，附加键是**电脑远端终端按键**，两者分开：

| 操作 | 用法 |
| --- | --- |
| 改尚未发送的草稿 | 用手机键盘的退格键 |
| 删除已经送到终端的字 | 点附加栏「退格」，删除远端光标前字符 |
| 提交远端当前输入 | 点附加栏 Enter；不连带发送手机草稿 |
| 输入一段文本 | 编辑手机输入框 → 发送箭头 → 需要执行时再点 Enter |
| 自动补全、取消 | Tab / Esc，具体行为由电脑程序决定 |
| 移动光标/程序导航 | ← ↑ ↓ → |
| 翻远端程序页面 | PgUp / PgDn（不是 App 本地滚动） |
| 中断、删词、行首等 | 点 Ctrl 后选择 Ctrl-C、Ctrl-W、Ctrl-U、Ctrl-A、Ctrl-E 等 |
| 按词移动等 | 点 Alt 后选择 Alt-B / Alt-F / Alt-D；支持输入其他组合 |
| Delete / Home / End / F1–F12 / Shift 组合 | 「输入方式」菜单 |

参考 Termux 附加按键的布局和键位种类，不引入第二套终端运行时。本版 Ctrl/Alt 是明确选择组合的菜单，**不是按下后影响之后所有打字的锁定修饰键**。暂不提供长按连续退格；每次按键经原有可靠投递流程确认后恢复可用，不排队重放。

屏幕较矮（例如键盘弹出）时收起第二排方向/翻页键，第一排的退格与 Enter 保留，所有收起按键仍可在「输入方式」找到。按钮目标至少 48dp（360dp 手机及以上验证）。

## 协议与安全边界

- 针对现有 Herdr 0.9.5 核对按键解析：`BSpace` 改为 `Backspace`，`C-w` / `M-f` 改为 `ctrl+w` / `alt+f` 等实际支持的名称。Ctrl-C 以外的 tmux 风格旧名称不能直接交给 Herdr。
- Herdr 的该命名解析器不识别 PageUp/PageDown/Home/End/Delete，这几项通过现有 `send_text` 发送固定 VT 控制序列；例如 PgUp = `ESC [ 5 ~`，不是把字符串 `PPage` 当成文字发送。其余按键走 `send_keys`。
- 保留精确 Agent/workspace/generation 身份校验、controller 权限和输入未确认保护；断线、只读、等待投递结果时不能发送。切换 Agent 或重建页面后的旧菜单不会把操作发给新 Agent。
- Ctrl-C、Ctrl-D 等是真实远端操作，可能中断任务或退出程序。没有在用户正在运行的生产 Agent 上发送测试按键；按键与故障场景在隔离 TCP + E2EE fixture 中验证。
