# 大图/工具输出后的中途消息补齐

此修复始于 Android 0.2.16 与本地 Relay `0.23.5+codexfix.10`，随 **Android 0.2.17 / Relay codexfix.11** 一并发布，修复“工具数持续变化，但中途文字和看图调用缺失”的问题。

## 原因

记录型会话的实时源读取最近 256 KiB 原始日志。一次看图返回的内嵌图片或大型工具输出可能大于这个窗口，把短小的 `view_image` 调用和紧随其后的文字挤到窗口之外。旧逻辑仅重新读取尾页；手机看到缓存中已有用户消息就提前停止补页，导致新命令仍能显示，但中间产生缺口。

这不是设计上把模型中途回复收进工具折叠：文字和图片应独立显示，只有工具参数/输出被折叠。

## 修复

- Relay 在近期窗口缺少上次已发布的最后一条记录时，用同会话的历史游标回读，找到连接点后按序发布中间记录。原始字节窗口移动本身不再被误判为源内容删除。
- 回读最多 32 步、1 MiB 条目和 1,000 条记录，受 8 秒上下文控制；未能找回连接点时仍让客户端重新同步，不猜测其他会话。
- Codex 结构化图片结果不再把 Base64 序列化为工具详情文本，保留正常文字块与简短图片标记；调用路径仍用于原有鉴权工作区图片预览。用户消息或原始日志不被改写。
- 手机在刷新/重新订阅时从新读到的页面补齐连续的最近轮次及已有连接点，不能用旧缓存里的用户气泡作为“已补齐”证据。中间页按已知记录位置插入，不追加到最新消息之后。
- 手机补读受 32 页、2 MiB/1,800 条以及时间边界限制；界面显示补齐进度，达到边界时标记可能不完整。历史准备响应和网络请求仍使用各自超时，不保证极慢网络的固定完成时限。
- 换会话、取消等待及新一轮重新订阅会丢弃旧请求/轮询结果。图片与模型文字在工具双层折叠外继续显示，不依赖用户展开工具。

只读验证不触发 Agent 新任务、不重启 Agent，也不上传真实会话内容。已删除或已覆盖的图片文件仍无法按历史原样恢复；该对话修复本身不放宽图片访问权限。工作区外文件默认拒绝，0.2.17 起可由用户另行启用[工作区外只读访问](file-access.md)。
